# Проверка версии 0.1.0

Локальная проверка: **17 ноября 2026**. Хост — Ubuntu 26.04, WSL2 Linux `6.18.33.2-microsoft-standard-WSL2`, Go 1.27.3. Контейнеры используют то же ядро хоста. Проверки не изменяли сеть хоста и не использовали действующие подписки.

| Проверка | Результат |
| --- | --- |
| `go test -race -ldflags=-checklinkname=0 ./cmd/... ./internal/...` | пройдено |
| Полный `go test -race -ldflags=-checklinkname=0 ./...` в native | пройдено: mobile, share, vkturn, включая mock packet round trips |
| `go vet ./cmd/... ./internal/...` | пройдено |
| Проверка снимка native по SHA-256 | 89 файлов, совпадение |
| Статический Linux amd64, GOAMD64=v1 | собран; ldd подтверждает отсутствие динамических зависимостей |
| Статический Linux arm64 | cross-сборка и .deb выполнены; запуск на ARM-устройстве не проверялся |
| Ubuntu 20.04 / 22.04 / 24.04 / 26.04 | CLI version/import/list и Tk-окно под Xvfb: пройдено |
| Установка .deb через apt, Ubuntu 20.04 и 26.04 | зависимости разрешены, пакет установлен, CLI/GUI-тесты пройдены |
| Реальный TUN и ip rule в отдельном user/network namespace | создание, применение маршрутов и полный откат: пройдено |
| Linux TUN → Xray VLESS → локальный mock-сервер → HTTP-ответ | пройдено на Ubuntu 20.04 и 26.04 |
| Завершение VPN по EOF stdin, потере stdout/SIGPIPE, SIGTERM и команде stop | все четыре сценария пройдены на 20.04 и 26.04; правила восстановлены, blink0 удалён |
| Ошибка каждого шага настройки маршрутов/DNS | откат проверен fake runner; повторная попытка неудавшегося удаления также проверена |
| Импорт, приватные права и атомарная запись, дедупликация, ревизии | пройдено |
| HTTPS-only, редактирование ошибок без токенов, Hiddify/Clash без повторного декодирования URL | пройдено |
| Дубли ID/JSON-ключей, срок подписки, лимит 1 МиБ | пройдено |
| GUI: фильтр, выбор, создание окна и безопасные VK URL | пройдено на всех четырёх контейнерных версиях |

В тесте передачи данных Python создаёт локальный минимальный VLESS-сервер на loopback и проверяет UUID, адрес назначения и HTTP-ответ. Запрос к синтетическому `198.18.0.1:8080` действительно проходит через системный TUN и пакетный стек; доступ к внешнему VPN-серверу для этого не нужен.

В package-smoke.sh `resolvectl` заменяется заглушкой **только внутри одноразового тестового контейнера**, поскольку systemd там не PID 1. Поэтому взаимодействие с настоящим resolved через D-Bus и Polkit-диалог в полноценной рабочей GNOME-сессии не проверялись. Проверка Tk под Xvfb подтверждает создание окна и поведение виджетов, а не работу оконного менеджера/Polkit агента.

Не проверялись: реальный Ubuntu 20.04 с ядром 5.4, физические ARM64-устройства, внешний VPN-сервер, живой VK TURN и CAPTCHA. Нет оснований считать контейнерный smoke-тест полной проверкой всех серверных сочетаний. Эти границы не отменяют результат проверки форматов, сборки, TUN-трафика и управления маршрутами.

## Воспроизведение

```bash
source tools/env.sh
./tools/test.sh
./tools/test-netns.sh
./tools/build.sh

# CLI и окно на целевой версии:
docker run --rm -v "$PWD:/project" -e BLINK_UBUNTU_VERSION=20.04 \
  ubuntu:20.04 bash /project/tools/compatibility.sh

# Установка .deb, настоящий TUN/HTTP и остановка; только отдельная сеть контейнера:
docker run --rm --cap-add NET_ADMIN --device /dev/net/tun \
  -v "$PWD:/project" ubuntu:20.04 bash /project/tools/package-smoke.sh
```

В fixtures находятся только синтетические данные. Истёкший Vokop fixture проверяется с фиксированным тестовым временем; его нельзя использовать как действующую подписку.
