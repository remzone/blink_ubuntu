# Архитектура

`cmd/blink` предоставляет CLI и приватный процесс `session`. `gui/blink_gui.py` — GUI на Python/Tk 8.6, совместимый с Python 3.8. Он вызывает CLI без shell, получает список без секретов и передаёт выбранный профиль процессу `pkexec /usr/bin/blink session`. При использовании checkout Polkit показывает стандартный запрос для локального бинарника; установленный пакет содержит политику с точным `/usr/bin/blink`.

`internal/app` отвечает за импорт, Vokop-модель, загрузку подписок и хранилище. HTTPS использует системные CA; перенаправления разрешены до пяти раз в пределах исходных HTTPS host/port. Размер ответа ограничен 1 МиБ, 1024 профилями и 8 МиБ хранилища. Ошибка обновления не удаляет прежние данные. Обычные форматы разбираются vendored mobile/share-парсерами; Vokop адаптирован по Swift-модели iOS.

`native/` — автономный снимок Go-ядра Android, общего с iOS. Старое имя модуля сохранено намеренно, root go.mod ссылается только на `./native`. Для сборки не нужны соседние checkout. SHA-256 каждого файла находится в native-manifest.json; verify-native.py проверяет точность снимка. Пакет содержит geodata, поэтому после установки не загружает их из интернета.

## Linux-сеть

`internal/network` открывает `/dev/net/tun`, создаёт непостоянный `blink0` (`IFF_TUN | IFF_NO_PI`) и передаёт IP-пакеты через публичные `Engine.Input` / `PacketWriter`. Сокеты транспорта получают `SO_MARK=0xb11` и используют физическую сеть. Для Xray используется MTU 1280, для WG/AWG — конфигурация профиля. TURN с WG также получает адреса/DNS/AllowedIPs исходного WG-профиля.

Порядок policy routing для IPv4 и IPv6:

1. Приоритет 10101: mark 0xb11 → main, чтобы транспорт не замыкался в TUN.
2. Приоритет 10102: main suppress_prefixlength 0, чтобы сохранить конкретные локальные/административные маршруты, но не физический default.
3. Приоритет 10103: таблица 51831 с маршрутами профиля через blink0.

Для IPv6 в таблице также устанавливается unreachable default с высоким metric. Более конкретные IPv6 WG-маршруты либо настроенный WG default имеют приоритет; остальной глобальный IPv6 не уходит через физический default. Существующие конкретные main-маршруты сохраняются для обоих семейств. WG split tunnel в IPv4 ограничивается AllowedIPs: адреса вне них используют основной default.

DNS задаётся через `resolvectl dns blink0`, `domain blink0 ~.` и `default-route yes`. Физический интерфейс и /etc/resolv.conf не переписываются. Требуется использование resolved stub resolver системой; внешний DNS, зашитый приложением или в его DoH-настройках, следует маршрутам приложения. URI Xray перехватывают DNS внутри ядра; Xray JSON сохраняет свою DNS/routing-семантику.

Перед изменениями проверяются занятость blink0, таблицы и приоритетов. root flock `/run/blink-ubuntu.lock` запрещает второе подключение. Адреса, DNS, маршруты и MTU проверяются перед передачей в iproute2. Внешние команды запускаются по фиксированным системным путям и с очищенным окружением.

Маршруты устанавливаются после старта ядра; у TURN дополнительно ожидается `ready`. До готовности физическая сеть доступна для TURN и ручной проверки. Неудача на любом шаге запускает удаление уже добавленных правил и DNS в обратном порядке. SIGINT/SIGTERM/SIGHUP, закрытие stdin и потеря GUI также завершают сессию. Удаляются точные правила, добавленные этой сессией; main не очищается. Закрытие TUN fd удаляет интерфейс.

Это не постоянный kill switch: при отключении снова действует обычная сеть. Ядро Xray может оставаться запущенным, когда удалённый сервер не отвечает; наличие маршрута не доказывает доступность интернета. На системах со строгим rp_filter=1 для физического интерфейса policy routing может требовать предварительной настройки loose reverse-path filtering администратором; Ubuntu по умолчанию использует loose mode. Клиент не меняет глобальные sysctl.

## Аварийное завершение

SIGKILL не выполняет Go defer. Интерфейс исчезнет, но policy rules и IPv6 unreachable могут остаться. Убедитесь, что ни одна сессия Blink не работает и blink0 отсутствует. Затем удалите **только точные правила этой версии**:

```bash
for family in -4 -6; do
  sudo ip "$family" rule del priority 10101 fwmark 0xb11 lookup main
  sudo ip "$family" rule del priority 10102 lookup main suppress_prefixlength 0
  sudo ip "$family" rule del priority 10103 lookup 51831
done
sudo ip -6 route del unreachable default metric 42760 table 51831
```

Отсутствующие записи дадут ошибку «No such file or directory»; это нормально. Если администратор назначил эти приоритеты/таблицу другому ПО, сначала сверяйте `ip -4 rule`, `ip -6 rule` и содержимое таблицы. Не применяйте `ip rule flush` и не удаляйте чужие маршруты. Перезагрузка также удаляет непостоянные записи.

## Протокол IPC

Первая строка stdin `blink session` — JSON объекта Profile (`id`, `name`, `kind`, `raw`). Затем идут строковые JSON-команды `stop` или `captcha` с `id`, `kind=key|token`, `value`. EOF означает отключение. stdout — NDJSON: `state`, `routed`, `stats` (`tx`, `rx`), однократный `captcha` и результат `captcha_accepted`. Ошибки — stderr и ненулевой exit status. SIGPIPE игнорируется, чтобы закрытие GUI проходило через откат.

CAPTCHA содержит приватные URL/идентификаторы. Не сохраняйте stdout session/connect при проверке реальных подписок. Публичный список и события статистики не содержат профиль или URL подписки. GUI не сохраняет challenge, success token или вывод IPC в журнал.

## Встроенная CAPTCHA и CLI 0.2.1

`gui/captcha_window.py` — непривилегированный процесс GTK/WebKit с отдельным ephemeral context для каждого challenge. Он получает challenge по stdin и возвращает один результат по stdout. Web SDK 2.0.0 закреплён в gui/vendor; bridge размещён в именованном JS-мире только верхнего frame. Главное окно и CLI передают результат ядру только после проверки ID/срока; GUI дополнительно отбрасывает ответы предыдущего поколения соединения. CLI на рабочем столе сам открывает окно; headless-протокол session остаётся совместимым. Подробности — в CAPTCHA.md.
